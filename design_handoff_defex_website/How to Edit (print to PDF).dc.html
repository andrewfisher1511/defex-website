How to edit the DEFEX website

Where the files live, how to change anything safely, and how AI does the typing. Covers both phases: the design prototypes (now) and the built Astro site (after Claude Code builds it).

1 · Where to save the handoff folder

Download design_handoff_defex_website.zip from the chat, unzip it, and place the folder inside the website repo, at the top level:

defex-website/design_handoff_defex_website/

That is the folder Claude Code reads when you say "build the site from the handoff". Everything it needs is inside: the README build brief, the four specs, all eight page prototypes, logos, photos and app screenshots. Commit it to the repo so it is versioned with the code it describes.

2 · First-time setup — commit the folder and run Claude Code

Install once (skip anything already installed):

  • Git — git-scm.com → download for Windows → accept the defaults.
  • Node.js — nodejs.org → LTS version → accept the defaults.
  • Claude Code — open Terminal (or PowerShell) and run: npm install -g @anthropic-ai/claude-code

Commit the handoff folder — after unzipping it into the repo, run these four lines in Terminal, one at a time:

cd C:\Users\andre\Documents\defex-website git add "design_handoff_defex_website" git commit -m "Add rev2 design handoff package" git push

Line by line: cd moves into the repo folder · git add stages the new folder · git commit records it with a message · git push sends it to GitHub. Prefer buttons over commands? GitHub Desktop (desktop.github.com) does the same: open the repo, the folder appears under Changes, type the summary, press Commit to main, then Push origin.

Run Claude Code — from the same Terminal, still inside the repo:

claude

The first run opens a browser window to sign in with your Anthropic account. Once you see the prompt, paste:

Build the website rev2 from design_handoff_defex_website. Start with README.md, follow all four specs, and structure a content/ folder from day one per content-editing-spec.md. Work on a branch and give me the preview URL before merging anything.

Claude Code will propose a plan and ask permission before running commands — read the plan, approve, and check the preview URL it hands back before anything is merged. To stop at any time, type /exit.

3 · Editing now, in the design workspace

While the site is still a set of prototypes in the DEFEX-Brand workspace:

  • Text — click any headline, paragraph or label in the preview and type. It saves in place.
  • Images — drop your portrait onto the About page's photo slot; other photos are swapped by asking in chat ("use this photo for project 2, image 3").
  • Tweaks panel — hero photo choice, motion on/off and similar switches.
  • Anything bigger — describe it in chat; the change is made for you and the old version is kept.

4 · Editing the built site — the one rule

All words, projects, posts and settings live in a content/ folder, separate from the code. The build must be structured this way from day one (it is specified in the handoff README):

FILE WHAT IT CONTROLS
content/site.jsonPhone, email, hours, ABN, service area, hero copy, service one-liners, social URLs
content/projects/*.mdOne file per case study — title, tags, paragraphs, carousel images + captions
content/posts/*.mdOne file per blog post (the web versions of LinkedIn posts)
content/diagnostics.jsonThe Home-page defect-pin scenarios — images, pin positions, captions

5 · The three ways to make an edit

A — Claude Code (at the desk, best for anything).

  1. Open a terminal in the defex-website folder and run claude.
  2. Say what you want in plain English — "change the hours to 7:30am start", "add a project: podium remediation, Cronulla, tags waterproofing and superintendency, photos in ~/Desktop/cronulla, notes attached".
  3. It edits only content/, opens a branch, and gives you a preview link.
  4. Check the preview, then tell it to merge. Live in about a minute.

B — Claude GitHub app (from the phone, on site). Open the repo on github.com, create an issue describing the change ("new post — paste text below"), tag Claude. It commits to a branch; the preview link appears in the pull request; merging publishes.

C — Direct edit (30-second fixes). On github.com, open the content file, press the pencil icon, fix the typo, commit to a branch, merge. No AI involved.

6 · The sandbox — nothing goes live by accident

Every branch automatically gets its own private preview site on Cloudflare Pages (branch-name.defex-website.pages.dev). That preview IS the sandbox: the full site, with your change applied, at a link only you have. The public site changes only when you merge to main. Made a mistake anyway? Every change is a commit — reverting it restores the site exactly, in seconds.

7 · LinkedIn posts

Write once, publish twice — with the site as the source of truth. Draft the post as a content file (dictated notes are fine; AI writes it in the DEFEX voice), merge it, and a GitHub Action pushes the finished text and link to LinkedIn through a scheduler (Buffer or Typefully). Full automatic import FROM LinkedIn is restricted by their API; if you post there first, paste the text into a GitHub issue titled "new post" and the AI does the rest — a two-minute job.

8 · Guardrails the AI always obeys

These live in the repo's CLAUDE.md, so every AI edit respects them automatically:

  • Never claim professional indemnity insurance.
  • ABN stays as the placeholder until the real number is confirmed.
  • Service area is exactly "Sydney metro, occasionally Greater NSW."
  • Australian English, no exclamation marks, no emoji, one accent colour.
  • Projects stay general — no addresses or party names; testimonials only with written permission.
